# Pixel Hero Maker — firearm corrective underlay, phase-one native proof

**Status: isolated compiled-WebAssembly proof of concept, NOT a Pixel Hero Maker player release.**

This package contains the first test of a native corrective compositing *stage* for the current accepted `Pixel Hero Maker [v.80]` code baseline. It does **not** patch `Build/WebGL.wasm`, game assets, or the Windows/Web releases. The original v.80 native hand-color correction is not changed.

## Objective

A single compositing stage handles:

- **Cape**: one missing opaque red pixel at idle `(27,17)`;
- **Fire Lizard**: five corrected opaque colored pixels at idle `(27,18)`, `(26,19)`, `(27,19)`, `(26,20)`, `(27,20)`;
- **Apache Armor**: one pixel erased at idle `(27,17)`.

Coordinates are zero-based in the 64×64 first-idle tile, unlike pixel positions in the 20× cropped exports. The coordinates are mapped by matching the examples to the **actual v.80 Unity source texture atlas**, not by guessing from the cropped image. The matching alignment is `(27,8)` for the Cape and Apache PNG exports and `(23,5)` for Fire Lizard.

The helper receives the selected item **as a verified input from its caller** (test-only enums `1= Cape`, `2=Fire Lizard`, `3=Apache`). It also receives an independent firearm occlusion buffer. A pixel with any firearm alpha is never overwritten, so the stage operates visually behind the firearm; the caller's supplied visible composite remains otherwise unchanged. A true erasure sets RGBA to zero; a transparent paint layer would not have this effect.

Color corrections sample **existing unmodified sprite pixels** rather than storing fixed RGB: Cape `(27,18)` supplies its red, and Fire Lizard uses `(25,20)`, `(29,19)` and `(26,21)` for its color shades. This supports swatches in the prototype when those samples reflect the current selected palette; it is not proof of all actual Unity swatch variations.

`49` is the original Unity asset's **Texture2D pathID for Bolt** in `resources.assets`, not a confirmed Unity **item-selection ID**. In the prototype this value is provided as a verified test input; it must not be assumed to be the value used in live Unity's `CharacterEditor`. The occlusion buffer is drawn from that source texture's first idle cell, not measured from a live equipped/recolored `CharacterBuilder.Rebuild`.

## Run and reproduce

Requires Node.js 18+ for the bundled precompiled `.wasm`; no npm packages or internet connection.

```text
node test_native_underlay.js
node emit_native_outputs.js
```

The optional Python image regeneration script `render_outputs.py` requires Pillow and NumPy and uses the two source PNGs in each item folder under `references/`. The native module is compiled from `corrective_underlay.c` with Clang's `--target=wasm32-unknown-unknown`. The precompiled module is included.

`fixtures.json` embeds the exact current/fixed full 64×64 test frames and the source Bolt occlusion mask. The source PNG pairs are included separately for audit. `examples/` contains output PNGs **generated by executing the compiled native Wasm**, and `three-case-comparison.png` compares Current / native proof / Fix visually.

## Confirmed tests

- **3/3 exact comparisons**: output entire 64×64 frame matches the user-supplied `Fix` image, byte by byte, when aligned to the Unity atlas.
- **3/3 enlarged exports**: PNG RGBA pixels match the user's corresponding full-size `Fix` PNG exactly.
- **19/19 isolation tests**: pixel additions/replacements/erasure; unchanged non-target image pixels; original Bolt source-mask priority; blocking a would-be corrected pixel with opaque firearm alpha; simulated recolored swatches; no action for unknown item, AK-47 test texture, or unknown weapon; and no guessed color when a required source pixel is missing.
- v.80 WebAssembly SHA-256 remains `ca81e969c6cb6ea0c6cde67bf5006d526e948143583f2981d494082947d84cf4` in the separate baseline source tree.
- v.80 native hand-color tests: 6 native routine-order fixtures and 17 Cape/Back reference fixtures pass; existing browser/idle mock test passes.

## Integration NOT performed / not verified

**This is not yet a working fix in the shipped game.** Required before a player build:

1. Obtain actual live Unity category/item selections (not texture pathIDs) and verify independent append/source identity for Body, Armor, Cape and Bolt in native `CharacterBuilder.Rebuild`.
2. Confirm the current firearm **layer's** visible-alpha mask and its hand-marker behavior. The texture asset alpha is not guaranteed identical to the final generated firearm layer.
3. Insert the corrective stage at a verified point in the game's ordered pixel build, with proper item guards and preservation of all other layers and palettes. Test both replacement and removal against every intervening merge layer, especially Apache's erase.
4. Preserve the v.80 older-recolorer-then-filtered-recolorer order, the accepted idle hand marker behavior, preview/export, and read-only diagnostics.
5. Test a real running Unity game in both Web and Windows, including swatches and other equipped items. No live Unity test took place in this phase.

The current v.80 diagnostic interface can record native append-site provenance and first-idle layer inputs (the `PixelHero-v80-BuilderProvenance.json` comparison); a **Bolt-equipped** capture with each of the three items would help establish the missing live selection/source identity evidence. Its UI text refers historically to the AK-47, but the `readSnapshot` check accepts a present firearm; this has not yet been verified live with Bolt.

**Do not distribute this archive as `Pixel Hero Maker [v.81]`: it contains a standalone research module, not a modified game.**
