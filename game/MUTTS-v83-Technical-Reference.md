# MUTTS Pixel Generator [v.83] — Cross-firearm underlay development handoff

**Status:** Experimental. The user accepted all 12 Bolt corrections in v.82. No live Unity exports have yet confirmed this cross-firearm extension. **Baseline:** exact v.82 release, not v.80 or v.81. **Scope:** first 64x64 idle frame, naked Human/reference colors. No animation/tail/complex outfit support claimed.

## Native implementation and regression protection

- v.82 full WASM SHA-256: `c0f31dba2a77be97ccc30a678ea07261705e0ab379bd6d9356a109d402e54747`.
- Only function **71935** is replaced by the v.83 compiled native underlay helper. The build preserves all other existing function bodies byte-for-byte, the original builder function 5031, the accepted native hand routines 71933 and 71934 and their existing call order, all WASM imports/exports/globals, frozen `Build/WebGL.data`, Unity framework and loader, and the original direct WebGL preview/export flow.
- The accepted **Bolt branch from `prototype/native_underlay_v82.c` remains present unchanged in behavior**: alpha mask `0x3dbe5bbd`, twelve original full-current fingerprints, 12 correction sets and statuses 1–12. Non-Bolt masks dispatch to a new separate native branch. No new Unity layers are allocated: writes go into non-firearm arrays before final merge. An Apache erase clears all non-firearm layers at its visible correction pixel.
- The source artifact `firearms/source-idle.npz` contains 23 unmodified Unity firearm texture tile RGBA arrays (64×64 first idle). `firearms/fixtures-v83.json` includes all exact per-firearm texture/mask hashes and the 12 source character reference frames; generated by `generate_cross_firearm_v83.py`. The latter source must be run whenever modifying masks; it does not modify the user-provided originals.

## Firearm recognition and fail-closed matching

- Each firearm is keyed to a **full 64×64 alpha FNV-1a signature**, not merely 7/9 marker counts, so it will skip mutated or unknown guns. There are 23 distinct source alpha hashes, including Shotgun and GoldenEagle, which have no alpha-254 idle markers. The original native v.80 hand resolver remains authoritative.
- 255 first-idle locations are nontransparent in at least one of the 23 firearm source tiles. For the non-Bolt path, fingerprints are computed from the independent non-firearm layer composite over the other **3,841 fully gun-transparent locations**. Twelve reference signatures are distinct. This does *not* infer C# UI category IDs or independently prove the underlying geometry is identical between different firearm selections.
- For non-Bolt recognized item references, **only patch locations with current gun alpha zero** are considered. All exposed targets must match the original `Current` reference pixel exactly. All color-source samples (drawn from non-firearm native layers even when gun pixels cover them) must match original expected RGBA values. All checks happen before any mutation. Any mismatch returns a negative status and no pixels are changed. Writes are isolated to 64x64 idle; visible firearm pixels, other layers, original markers and animation frames remain unchanged.
- There are 55 correction sites across the twelve item rules. Different guns cover different subsets. For the 22 non-Bolt guns, the synthetic cross-mask tests found 142 item/weapon cases with at least one visible correction, and 122 cases where all sites were covered and should skip (-6).

## Status encoding

- Bolt: 1..12, same accepted v.82 item index.
- Non-Bolt: `100 * firearm ID + item ID` where firearm IDs are taken from `firearms/fixtures-v83.json` (1..22). `PixelHero-v83-IdleAutoHandTrace.json` maps those integers to human-readable firearm and item labels.
- 0 = no build observed; -1 = invalid native array/list; -2 = gun mask unknown; -3 = unknown reference character; -4 = color-source mismatch; -5 = original Bolt-specific firearm-occlusion rejection; -6 = all target pixels hidden; -7 = visible target fails `Current` match.
- `observedSpriteAtlas` is a read-only GPU observation and may not correspond to the same rebuild; a positive native status is not conclusive acceptance evidence.

## Test evidence and limitations

- `prototype/test_native_v83_integrated.js`: 281 compiled-WASM fixture checks: 23 source firearm masks x 12 reference character frames plus five adversarial tests, checking final target bytes, unchanged firearms, untouched non-target/non-idle atlas content, true erase, skips, and memory provenance. Synthetic fixtures do not recreate every live Unity selection.
- Inherited accepted v.82 functional behavior is preserved in source and synthetic regression. User live acceptance is established for all twelve **Bolt** cases, not the other guns. Multiple layers, swatches, user-defined colors, special poses and tail defects are outside this release; other firearms could select different underlying Unity inputs and rightfully skip.
- Main game WASM is compiled and validated. JS syntactic/browser-mock tests are separate from actual browser gameplay. Windows/Web packaged game content must remain identical; Windows exe is rebuilt from Go `//go:embed game`. Running it on Linux (through an equivalent smoke server) does not establish real Windows browser integration.
- Final downloaded artifact filenames via the receiving client cannot be guaranteed by filesystem names alone; follow `MUTTS_PIXEL_GENERATOR_PROJECT_RELEASE_RULES.md` §7 and report `NOT TESTED` if the user-facing download could not be performed.

## Future tests

Trigger a native rebuild, capture `SpriteSheet.png` and diagnostic `PixelHero-v83-IdleAutoHandTrace.json`, and compare to the expected underlay *visible through the actual gun mask*. If status -3 or -7 appears with an intended setup, inspect actual native source layers before expanding the guard. Do not disable checks or synthesize claimed live acceptance.
